# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- UI foundation (A1335, UI standard D366): design tokens `content/ui/tokens.json` and 9-slice frame data `content/ui/frames.json` (schemas `ui-tokens`, `ui-frames`); Godot-free `src/Game.Presentation` (ADR-0008) with UI/text scaling (75–200 %, B2513), WCAG contrast arithmetic and the standard's rules (min. 18 px text, contrast 4.5:1 / 3:1 / 7:1 high contrast, 4 px grid, frame margins); the game builds its theme at runtime (Atkinson Hyperlegible, driftwood frames as 9-slice when present, flat fallback otherwise) and applies the UI size via `ContentScaleFactor`; window building block `GwWindow`; display base 1920x1080 with `canvas_items`/`expand`. The headless smoke run checks a sample window in 1920x1080 and 3840x1600, UI 75/100/200 %, text 100/200 %, DE and EN (`UI_OK`).
- Text system DE/EN (KR4, ADR-0007): catalogs `content/i18n/{de,en}.json` with schema `i18n` and display texts for the whole vocabulary; the game embeds them at build time and loads them into Godot's TranslationServer (language switch at runtime, self-check in the headless smoke run). CI text check (`tests/Localization.Tests`): same keys and placeholders in both languages, every vocabulary id has a text, scenes and UI code show only keys (Roslyn scan), every used key exists.
- ADR-0008: UI and presentation logic in the Godot-free C# library `src/Game.Presentation`; `game/` keeps thin node scripts; no GDScript.
- Hardware detection in the AI service (GPU via nvidia-smi, CPU, RAM; standard library only) and tier selection from the data file `content/hardware/tiers.json` (schema `HardwareTiers`, thresholds with ~5 % tolerance, multi-GPU tier requires a second card of minimum size); `/health` reports the hardware and tier.
- Generated Python contract types use type aliases instead of RootModel wrappers (plain `str`/`int` values).
- AI service: `POST /decide` (B3) with per-request output schema (option ids as enum), schema check of the request before the model, up to two retries, ServiceError on failure (no substitute decision), mock and replay backends, JSONL call log; model queue, Ollama client, versioned prompts (decider prompt v1).
- AI service skeleton (`ai-service/`): FastAPI on 127.0.0.1 with OS-assigned port and ready line, `GET /health` (HealthStatus) probing Ollama and ComfyUI, session token and Host check, ServiceError bodies, configuration from `config.toml` / `GW_AI_*`.
- Contracts: `HealthStatus` schema; ServiceError codes `forbidden` and `not_found`.
- Contracts v0: JSON Schemas for DecisionRequest, DecisionResponse, ServiceError and vocabulary files, examples, vocabulary placeholders in `content/vocabulary/`, generated pydantic models (`glassworld_contracts`) and contract tests.
- uv workspace at the repository root (Python 3.12, `uv.lock`).
- Repository foundation: license, readme, contributing guide, folder layout, Git attributes and ignore rules.
- Architecture Decision Records ADR-0001 to ADR-0007 (versions, core without Godot, SQLite per world, construction-kit builder, one model for two roles, AI service lifecycle, data files and localization).
- .NET solution `GlassWorld.slnx` with `Simulation.Core` (no Godot) and xUnit v3 tests; shared build settings (net10.0, nullable, warnings as errors, analyzers, code style in build), central package versions, `.editorconfig`, `global.json` and repo-local `nuget.config`.
- Godot 4.7.2 .NET project in `game/` (start scene with camera, sun, island and water placeholders) referencing `Simulation.Core`; headless smoke test `tools/godot-smoke.sh` (600 frames, fails on errors, missing marker, timeout or exit code).
- CI (GitHub Actions): `dotnet` (format, build, test), `python` (uv locked sync, ruff, pyright, generated-model check, pytest with AI mock) and `godot-smoke` (verified Godot 4.7.2 mono download, 600 headless frames); actions pinned to commit SHAs.
- `game/GlassWorld.Game.sln` so Godot can export the C# project; the game runs with the invariant culture (module initializer) and culture-sensitive APIs are build errors (CA1304/1305/1307/1309/1310/1311).
- C# contract types generated from `contracts/schemas` (`tools/ContractGen`, `--check` in CI) and runtime validation: `ContractSerializer` checks every message against the embedded schemas before deserializing and after serializing; `contracts/content-map.json` assigns every `content/` file to its schema.
- Simulation core B1-1: world time without an earth calendar from `content/world/time.json` (1 game day = 20 real minutes at normal speed, 7 days per season), fixed tick with time boundary events, PCG32 with named seed streams, SHA-256 state hash with a cross-platform golden test, banned non-deterministic APIs, headless runner `src/Simulation.Headless`.
- Simulation core B1-2: object model "the world knows the truth": object types with true properties (`content/objects`, schema `object-types`), combination rules matched by properties, not types (`content/rules`, schema `combination-rules`, new action `combine`), world objects with stable ids, inhabitant beliefs separate from truth, `ContentSet` loading every file through the contract validator with cross-file checks.
- Simulation core B1-3: inhabitants with needs, feelings, traits (registers from data, not enums), will to live that only sinks after long neglect, start inhabitants from the world seed; action effects decided by the target's true properties (`content/effects`); routine layer (utility AI) with weights and point-table curves from data (`content/behaviour/utility.json`) that sees only beliefs; learning from experience as a frame for B4a.
- Simulation core B1-4: decider port with mock and replay, open questions with waiting list (W1595: whatever an inhabitant does not understand becomes a question; B2487), answers take effect at the next tick boundary and are logged, deterministic UUIDv8 request ids, player command `inhabitant_clicked`, read-only `WorldView` snapshots for the UI.
- Simulation core B1-5: save games in SQLite (`Simulation.Data`, schema version, migrations, crash-safe swap) with autosave after every game day; placeholder start world with two pairs (F5249); spark rule pyrite + flint; the game shows the core world and the smoke test checks it (`WORLD_OK`); headless acceptance runner (`src/Simulation.Headless`).
- `src/AiClient`: HTTP decider port to the local AI service (`POST /decide`, session token); an unreachable service becomes a retryable `model_unavailable`, so questions wait and inhabitants live on in routine mode (B3 S6, acceptance A3/A6).
