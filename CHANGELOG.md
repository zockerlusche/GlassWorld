### Added

- The nightly look back, core side, step 1 (A1581/A1585, B2687; off in the shipped data): with `knowledge.review.enabled` the compute night sends one `review` job per inhabitant instead of the memory job (same batch rule), with its Fundbuch (beliefs, experienced and heard first, at most `knowledge_max`), ideas, needs, character and the actions an intention may name (data). The core checks the answer again (GW1 #22713): an idea's roots must be beliefs, ideas or known names of this inhabitant, an intention's action one of the data's and its subject a type it believes something about; anything else is dropped and logged. Thoughts and the dream become `thought` / `dreamed` events, a new or grown idea an `idea` event (vocabulary, DE/EN). Offering intentions in a free moment and a ripe idea as the invention wish follow in step 2.

- What was built gets used: the builder knows its work, the routine uses made things (D9, B4b; Marcel's rule PR2 "frame, not outcome", W1820). **All values are proposals (Vorschlagswerte) for Marcel's list.** **Cause** (18-day run with the live AI, seed 1): the chain ran from `invention_wanted` to `built` (9 inventions, 6 built), but `first_use` never came. Two gaps: the routine had no consideration for `use` (only the decider could choose it), and the invention system registered the new type's true properties but wrote no belief - the routine acts on beliefs only, so a built thing was an unknown thing to its own maker. **Knowing what one made (`InventionSystem`, when the thing stands):** *whoever built it* now believes by its own doing what every invention is by being made - the `implied_properties` of `content/invention/settings.json` (today `crafted`), nothing else - as experience, through the one path every experience takes (new `InhabitantsSystem.Experience`, which a finished action uses too: source `experienced`, `experienced_confidence`, over what was heard with the trust change for the teller, `knowledge_gained` with `/experienced`, action = the building step; the existing event effect for found-out knowledge applies, `purpose` +0.05). The building task knows one builder, the inventor; there are no helpers. *Whoever had the idea* (the inventor, whose wish it came from) holds the properties the invention introduces as its own guesses: source `guessed`, as sure as a guess can be (`guessed_cap`), never over a belief it has (new `InhabitantsSystem.Guess`, `knowledge_gained` with `/guessed`, which has no event effect). Nobody else learns anything. Guesses are replaced the usual way: looking shows the visible properties (`seen` over a weaker guess), an action teaches what its effect rules depend on. `use` teaches `crafted` only, because its one effect rule depends on `crafted` only; further effect rules of `use` on other properties (data) would let the world decide and the use teach them - none added here. **Using it (data only):** one new consideration in `content/behaviour/utility.json` - `use` on things believed `crafted` for the need `purpose`, weight 0.3, curve [[0, 1], [0.6, 0.8], [0.85, 0], [1, 0]], `yields_to_needs` true, no `search_action`. The line names a property and a need, no type and no invention; the brain is unchanged. Whether a use helps is decided by the world from the true property (the existing effect rule of `use` on `crafted`: `purpose` +0.15, `joy` +0.05): someone who wrongly believes a stone is made tries it once, gets nothing, knows better (`found_out`) and leaves it. **Why these values:** 0.85 is where one more use would fill the need past its top; next to its thing with the body's needs met the wish beats standing around (`idle` 0.1) while `purpose` is below about 0.75, so a maker catches up (in the test from 0.15: five uses in 45 minutes) and then uses its thing about once in 30 hours (the need's decay of 0.005 per hour against +0.15 per use) - not all day.
